# Design Principles — AI Canvas Portfolio

実装時に必ず全項目を確認すること。

---

## 核心思想

- AIベースの動的コンテンツ生成時代のUI。ページ・スクロールという紙の本の概念を排除
- 訪問者に「これは従来のサイトではない」と実感させる
- コーディングの制約による固定化されたデザインから解放する

---

## デザイン要件

1. **2Dに縛られない** — perspective、parallax、深度で空間を作る
2. **カード・矩形セクション禁止** — 放射状・不規則な配置を使う
3. **スクロール不要** — 1ビューポートに全情報を空間配置
4. **アニメーション超リッチ** — サイトが生きていると思わせる
5. **常に不規則に動く** — 静止要素は存在しない。全てがオーガニックに漂う
6. **情報密度を高く** — 余白=良いデザインという常識を疑う。AIは情報量が多い方が適している

---

## UX要件

1. **全要素に意味を持たせる** — 位置・アニメーション・存在理由を明確に
2. **HTML/CSS/JSの制約を疑う** — 「この表示は技術的制約では？本来はどう見せたい？」
3. **状態遷移のUX** — 不要になった要素は退場アニメーションで消す
4. **ノード自体が詳細になる** — 別パネルではなくノード自体がインライン展開する
5. **ホバーで他をディム** — フォーカスしたノード以外は暗く退く
6. **クリックでズームイン** — 太陽系の惑星に着陸するアニメーション
7. **ホバー認識領域は広めに** — 小さすぎるとUXが悪い
8. **メディア対応** — ホバー/展開時に画像やGIFを表示可能にする

---

## アニメーション哲学

- パフォーマンスのためにアニメーションを削除しない
- 単純なアニメーション（fade, linear easing）はプログラムで書いたものだとわかり感動しない
- **AIがそのコンテンツを提供してきたと思わせるアニメーション**が必須
- CSS `@keyframes` をcompositorスレッドで実行し、JSオーバーヘッドを回避
- 繰り返しアニメーション → CSS keyframes、インタラクティブ遷移 → Framer Motion

### AI風アニメーションパターン

- **ai-breathe**: オーガニックな脈動。不規則なリズムでopacity/translateYが変化
- **ai-reveal**: コンテンツがAIによって生成されているかのようにスタガーで出現
- **Spring physics**: 機械的でない有機的な動き（stiffness: 60, damping: 18）

---

## パフォーマンス要件

1. **GPU合成プロパティのみ** — `transform`, `opacity`のみアニメーション（`background`, `filter`のlayoutプロパティ禁止）
2. **will-change** — 頻繁にアニメーションする要素にのみ付与（過剰使用禁止）
3. **パーティクル制御** — デバイス/ノード数に応じて削減: `Math.max(6, 12 - nodes.length)`
4. **useMemoでレイアウト計算キャッシュ** — 再レンダーごとの再計算を防止
5. **MotionValue活用** — マウス座標はstateではなくMotionValueで（不要な再レンダー防止）
6. **条件付きレンダリング** — 見えない要素はDOMに出さない
7. **CSS containment** — `contain: layout paint` でレイアウトの影響範囲を制限
8. **isolation: isolate** — 各レイヤーのスタッキングコンテキストを確実に分離

---

## スケーラビリティ

- ノード配置は動的計算（`computeLayout()`）
  - ≤6ノード: 軌道半径33vw, スケール0.85
  - ≤9ノード: 軌道半径28vw, スケール0.75
  - 10+ノード: 軌道半径24vw, スケール0.68
- 楕円軌道: Y圧縮率0.55で奥行き感を演出
- ノード増加時はパーティクル数・接続線を自動削減

---

## レイヤー構造（Z-index）

下から順に:

1. **Background** (DepthLayer depth=3) — グラデーションメッシュ、軌道リング
2. **Center Identity** (z-[1]) — 名前・タイトル・ロケーション
3. **Particles & Neural Lines** (z-[2]) — パーティクル、接続線、パルス
4. **Content Nodes** (z-[30]) — プロジェクト・スキル・キャリア・バリューのノード
5. **Foreground** (z-[40]) — コンタクトリンク、マウスグロー
6. **Expanded Overlay** (z-[100]/[101]) — クリック詳細モーダル

---

## 技術的注意

- **Next.js 16 + React 19 hydration**: `mounted`パターンでSSR/クライアント差分を回避
- **Framer Motion 12**: `ease`配列には`as const`必須
- **`cz-shortcut-listen`等のhydrationエラー**: ブラウザ拡張機能が原因（コード側の問題ではない）
- **3D stacking context**: `perspective` + `rotateX/Y`使用時、DOM描画順序とz-indexの両方で正しくレイヤーを制御する
- **FloatingNodeの`entered`パターン**: 初期遅延付きエントリーアニメーションとホバー遷移を分離するため、`setTimeout`後に`entered=true`として別のtransitionに切り替える
